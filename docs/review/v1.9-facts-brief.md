## 2. 渲染链路盘点（决定预览用哪条）

| 链路 | 位置 | 特点 | 适合随航预览吗 |
|---|---|---|---|
| A. tiptap WYSIWYG 实例 | `src/editor/useEditor.ts` + `src/editor/extensions.ts` | 项目主渲染链路；带全部插件（代码块 highlight.js、KaTeX、表格、find 装饰、focus 装饰）；**所见即所得与它像素级一致** | **推荐** |
| B. Rust pulldown-cmark + HTML 字符串 | `src/export.ts` `buildExportHtml()` | 走 IPC 异步；带 base64 图片内嵌与打印 CSS；**渲染结果与 tiptap 不一致**（表格/公式/代码块实现不同）；每次输入走一次 Rust 往返 | 不推荐 |
| C. `MwtyperMarkdownManager` | `src/editor/markdown-serde.ts` | 只是 md ⇄ PM JSON 的编解码器，不产出 DOM | 配合 A 使用 |

**A 链路的关键事实**：
- `markdown.parse(body)` → PM JSON；`markdown.serialize(json)` → Markdown 字符串。
- `ed.commands.setContent(json, { emitUpdate: false })` —— **`emitUpdate:false` 可避免触发 `onUpdate` → `markChanged`**，即不会把文档误标为脏。这是「源码侧改动实时反映到预览」而不污染保存状态的关键。
- `setContent` 会重置选区并把视口定位到文档开头（已实测，见 `editor-probe3.ts` G-2）——**预览侧滚动联动必须自己维护，不能依赖 setContent 保留滚动位置**。
- ProseMirror 可编程控制滚动：`view.dispatch(tr.setScrollTop(px))`。
- CodeMirror 6 可编程控制滚动：`view.dispatch({ effects: EditorView.scrollIntoView(pos, { y: "center" }) })`。
- `src/editor/caret.ts` 已有 `pmPosToTextOffset(doc, pos)`（PM 位置 → Markdown 字符偏移）与 `restoreCaret(ed, saved)`，
  **随航的「源码光标 → 预览位置」映射可直接复用前者**。

## 7. 随航编辑若复用 tiptap 实例做预览——**状态归属的 6 个坑**（主理人推导，务必逐条处理）

随航模式下 **CodeMirror 是「事实源」**，tiptap 实例退化为**只读渲染器**。但现有代码里有 6 处默认「tiptap 是事实源」的逻辑，若不处理就会出现「预览和正文不一致」「脏标记错乱」「保存了旧内容」这类问题：

| # | 位置 | 现状逻辑 | 随航下的问题 | 必须怎么改 |
|---|---|---|---|---|
| 1 | `src/App.tsx` `currentText()`（约第 191 行） | `if (modeRef.current === "source") return sourceTextRef.current;` 否则返回 tiptap 序列化结果 | 随航模式下事实源是 CM，但这里会返回 tiptap 的序列化结果 → **保存的是预览内容而非用户输入** | 随航也要返回 `sourceTextRef.current` |
| 2 | `toSource()`（约第 680 行） | 无条件 `markdown.serialize(ed.getJSON())` 覆盖 `sourceTextRef` | 在随航模式下调 `toSource` 会**用预览内容覆盖用户正在编辑的源码** | 随航模式下 `toSource` 不应重算正文（或直接 no-op） |
| 3 | `toWysiwyg()`（约第 700 行） | `if (sourceTextRef.current !== lastMdRef.current) setContent(parse(body))` | 随航已用 CM 内容 setContent 过预览；再切到 WYSIWYG 时若条件判断不严谨，会**用旧内容覆盖** | 随航 → WYSIWYG 的交接必须保证「WYSIWYG 拿到的是 CM 里的最新文本」 |
| 4 | `onSourceChange`（约第 583 行） | 已正确调用 `markChanged()` | ✅ 无需改 | —— |
| 5 | `loadBuffer()`（约第 329 行） | `editorRef.current?.commands.setContent(markdown.parse(body), { emitUpdate: false })` + `sourceTextRef.current = tab.text` | 切标签时预览与源码都要换成新文件 | 随航下应**同时**更新两栏；注意顺序（先设 `sourceTextRef` 再 setContent） |
| 6 | `src/editor/caret.ts` `pmPosToTextOffset` | PM 位置 → Markdown 字符偏移 | 随航的「源码光标 → 预览滚动位置」映射可直接复用它 | 直接复用，不要另写 |

**另需注意**：
- 预览侧滚动位置**不能靠 `setContent` 保留**（实测 setContent 会把视口重置到文档开头，见 `editor-probe3.ts` G-2）→ 必须在 setContent 之后用 `view.dispatch(tr.setScrollTop(px))` 主动恢复。
- 预览同步需要**防抖**（建议 120–200ms），否则每次按键都触发一次完整 markdown 解析 + PM 文档重建。
- 滚动联动必须有**「谁在动」的单向锁**（如 `syncLock` 标志 + 250ms 冷却），否则两边互相 `scrollTo` 会形成抖动/无限循环 —— 这是这类功能最常见的体验缺陷。
- `editor.setEditable(false, false)` 让预览不可编辑；但要确认这不会让 `findReplace` / `focusMode` 插件报错。
- 预览栏若复用 `elementRef`，其 CSS 需从 `.editor-wrap`（独占整宽）改为「右栏宽度自适应」，并且**不能**再有 `display:none`（否则 PM 会停止测量）。
